Refuses a save from a stale copy of a term, and leases a term to the editor who has it open. `term.update` now requires `ifMatch`, the `etag` that `term.get`, `term.list`, `term.create`, `term.update` and `term.delete` return in place of the raw `version` field. A missing `ifMatch` is a `BAD_REQUEST` that says where the `etag` comes from. A stale one is a `CONFLICT` with reason `etag_mismatch`, carrying the current `etag` and whoever holds the term's edit lease, and the save changes nothing. The check runs in the write itself, so two saves from the same copy can't both land. Deleting a term moves the token of every child it re-parents, and `plumix import` and `plumix sync` move each replaced term's token past the one the site held, so a copy opened before the load conflicts instead of saving over it. A meta settle on `term.get` still leaves the token alone. `terms.version` now moves by one on any update that doesn't set it.

The new `term.lease.acquire` (`takeOver` optional), `term.lease.renew` and `term.lease.release` procedures drive a term's edit lease, and `term.update` refuses a write from anyone but the holder with `LOCKED`, unless it passes `takeOver: true`. In the admin, the term editor opens read-only with a banner while another user holds the lease, offering **Take over** and **Back**. A save from a stale copy opens the conflict dialog, with **Compare**, **Keep mine** and **Load theirs**.

`plumix/db` adds `claimVersion`, `parseVersionIfMatch` and `versionIfMatchObject`, the `version`-token forms of `claim`, `parseIfMatch` and `ifMatchObject`, and `claimTerm` and `assertTermCopyCurrent`, the claim and early check `term.update` makes, for a plugin that edits a term. `etagOf` and `ConflictError` also take a `version`; a conflict from one carries no `updatedAt`. `plumix/admin` adds the edit-lease session the admin's editors use (`createEditLeaseSession`, `editorLeaseMode`, `lockedBy`) and `etagConflict`, which reads a stale-copy `CONFLICT`.
