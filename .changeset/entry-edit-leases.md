Adds edit leases, so a second editor can no longer overwrite an entry someone else is editing. Opening an entry in the admin leases it to you, renews the lease every 30 seconds while the editor is open, and releases it when you leave. A lease lapses 120 seconds after its last renewal. While another user holds the lease, the editor opens read-only with a banner saying who is editing and since when, and offers **Take over** and **Back**. If someone takes over from you, your editor turns read-only, keeps your unsaved changes on screen, and says who took over and when. The conflict dialog also names who is editing the entry now.

The server enforces the lease on every surface. `entry.update`, `entry.publish` and `entry.revisions.restore` refuse a write from anyone but the holder with the new `LOCKED` error (HTTP 423), carrying `{ holder: { id, name }, since }`, unless the caller passes `takeOver: true`, which takes the lease over. A write with no lease is allowed, and system writes such as trash, restore and scheduled publishing ignore leases. A `CONFLICT` with reason `etag_mismatch` now also carries the lease `holder` when there is one. The new `entry.lease.acquire` (`takeOver` optional), `entry.lease.renew` (answers `{ lease }` or `{ lost: { by, at } }`) and `entry.lease.release` procedures drive the lease.

`plumix/db` adds the helpers a plugin's own editable table can use for the same lease: `acquireEditLease`, `renewEditLease`, `takeOverEditLease`, `releaseEditLease`, `readEditLease`, `assertWritable`, `LockedError` and `EDIT_LEASE_DURATION_MS`. `ConflictError` takes the resource it guards as an optional second argument, so its conflict names the holder. `plumix/admin` adds `EDIT_LEASE_RENEW_INTERVAL_MS`. A new `edit_leases` table ships in core's migrations, and `plumix/schema` exports it as `editLeases`, with `EDIT_LEASE_SURFACES`.
