Moves users and authentication to the event and filter API. `user` and `auth` are exported from `plumix/plugin`. `user` holds the events `user.invited`, `user.updated`, `user.metaChanged`, `user.statusChanged` and `user.deleted`, and the filters on the user RPC procedures, `user.listInput` and `user.listOutput` through `user.deleteOutput`, which behave as before. `auth` holds `auth.signedIn`, `auth.signedOut`, `auth.registered`, `auth.emailChangeRequested`, `auth.emailChanged`, `auth.credentialCreated`, `auth.credentialRevoked`, `auth.credentialRenamed`, `auth.oauthAccountUnlinked`, `auth.sessionRevoked`, `auth.apiTokenCreated`, `auth.apiTokenRevoked`, `auth.deviceCodeApproved` and `auth.deviceCodeDenied`. Each event fires where its string name did, and its handler takes one payload object and the request `ctx`. `ctx.events.emit` now takes a payload written inline for an event whose payload holds a literal union.

Breaking: the `user:*`, `credential:*`, `session:revoked`, `api_token:*`, `device_code:*`, `oauth_account:unlinked` and `rpc:user.*` string names are removed. Replace `addAction("user:signed_in", (user, { method, provider, firstSignIn }, ctx) => …)` with `ctx.events.on(auth.signedIn, ({ user, method, provider, firstSignIn }, ctx) => …)`, `addAction("user:updated", (user, previous) => …)` with `ctx.events.on(user.updated, ({ user, previous }) => …)`, and `addFilter("rpc:user.list:input", …)` with `ctx.filters.add(user.listInput, …)`. A payload's positional context now sits beside the subject under its own key: `{ user, enabled }`, `{ user, reassignedTo }`, `{ user: { id }, changes }`, `{ credential, actor }`, `{ apiToken, actor, mode }`, `{ deviceCode, actor }`, `{ session, actor, mode }`, `{ oauthAccount, actor }`. `user:meta_changed` and `user:status_changed` are `user.metaChanged` and `user.statusChanged`; `user:registered`, `user:signed_in`, `user:signed_out`, `user:email_change_requested` and `user:email_changed` move to `auth`.
